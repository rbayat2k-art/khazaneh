## دامنه و هویت

درخواست مالک: خزانه یک سازمان از چند حساب با صاحبان حقوقی مختلف استفاده می‌کند و باید همه مبدأها را ببیند. [ADR-024](../decisions/ADR-024-shared-organization-source-bank-accounts.md) تفکیک source-account pool از شرکت درخواست/پرداخت دستی را مشخص می‌کند. فقط Staging؛ Production، رمز/نقش/سقف و داده‌های قدیمی تغییر نکنند.

شاخه `codex/shared-source-bank-accounts-v59`، HEAD مبنا `6d5882b5d27a8f600b714cb4d1f3c97831cb7bc6`. تغییرات قبلی v51–v58b دست‌نخورده‌اند؛ Git commit/push انجام نشده است. artifact نهایی `ops/work/domain-release-multi-role-shared-source-banks-v59-20261025b`، manifest=`97de76290053238a9c06088a7311fff178f668b59ae45f9a94e052686243df34`،۳۷خروجی و۱۴۷منبع build. `ops` همان پروژه خصوصی انتشار موقت khazaneh است. artifact میانی با پسوند۲۰۲۶۱۰۲۵ و manifest4dd58c… محفوظ است؛ فقط اصلاح اسکرول موبایلِ جدول باعث build تازه شد، server.cjs هر دو SHA256=`02897f7603dcc97981e1819b196200340dfdd2f90cb6fd317732efbdb0d4b2a9` دارد.

## تغییر و حفاظت

UI/API از policy مستقل حساب‌های مبدأ استفاده می‌کنند؛ permission موجود خواندن/مدیریت حساب یا اجرای/ثبت پرداخت برای نیاز عملیاتی خودش فهرست را می‌گیرد. متقاضی عادی یا نشست تغییررمز اجباری نمی‌گیرد. ویرایش/غیرفعال‌سازی/import/default همان کنترل قبلی را دارند؛ UI hint سروری فقط عملیات واقعاً مجاز همان حساب را فعال نشان می‌دهد. حساب غیرفعال در فهرست هست ولی در انتخابگر/فرمان پرداخت مصرف نمی‌شود.

پرداخت به درخواست غیرمجاز با حساب مشترک همچنان ممنوع است. manual جدید شرکت تراکنش سروری ثبت‌کننده را مستقل از صاحب حساب دارد؛ نمایش، گزارش، فیلتر، اکسل و رسید به آن احترام می‌گذارند. ADMIN صرفاً سیستمیِ فاقد شرکت عملیاتی، زمینه legacy خود را حفظ می‌کند تا شرکت هزینه اختراع/پنهان نشود. سوابق قدیمی بازنویسی نشده‌اند. schema۱، بدون migration/reset؛ rollback با CURRENT data و roll-forward سازگار، نه DB یا binary قدیمی.

بازبین مستقل خواندنی مرز مجوز، legacy، مالکیت manual و downstreamها را بررسی کرد؛ در feature مانع تازه ندید. پیشنهاد تست مستقیم ADMIN دارای شرکت VALID بود و اجرا شد. بازبین هویت دو backend و محدودیت JSON را نیز بررسی کرد؛ شرط تحویل محدود SQLite را PASS بازاجرای نهایی دانست. چون rerun دوباره FAIL شد، این شرط برقرار نیست و cutover متوقف ماند. بازبین تست یا داده واقعی اجرا/تغییر نداد. پنج finding قدیمی ممیزی v55 خارج این تغییر باز می‌مانند؛ هیچ سلامت کلی یا مجوز Production ادعا نمی‌شود.

## Staging، بازیابی و پذیرش

root هدف `ops/private/permanent-staging-shared-source-banks-v59` هنوز ساخته/فعال نشده؛ هیچ stop/backup-transfer/cutover روی Stage جاری انجام نشد. URL ثابت `http://127.0.0.1:55120/` همچنان v58b قبلی است، نه این feature. پس از رفع گیت، cutover فقط با بکاپ تازه جاری SQLite و restore مستقل، تطبیق کل state، کپی opaque vault و ACCESS و حفظ root قبلی مجاز است. ابزارهای آماده به معنای اجرای موفق نیستند؛ `finalize.mjs` عمداً اجرا نشد.

آزمون مالک پس از آماده‌شدن: با treasury «بانک‌ها و شماره‌حساب‌ها» را باز کند؛ همه مبدأهای ثبت‌شده سازمان، حتی صاحب حقوقی دیگر دیده شوند. در فرم پرداخت و ثبت پرداخت انجام‌شده، حساب فعال دیگر را با جست‌وجو انتخاب کند؛ حساب غیرفعال قابل انتخاب نباشد. دو پرداخت جزئی از دو مبدأ در پرداخت‌شده‌ها و خروجی دو نوبت مستقل بمانند. درخواست شرکت غیرمجاز یا ویرایش حساب بدون اختیار باز نشود.
