## تغییرات و حفظ سازگاری

۹ کارت با نام دقیق منو، ۶۵ کنترل، ۴۰ مسیر زیرمنوی اصلی و کنترل جداگانهٔ راهنمای میانبر وجود دارند. فرم‌های ثبت و کارتابل پیگیری دو کارت جدا هستند. چهار اختیار واقعی ثبت، ارسال مجدد اصلاحیه و عملیات خزانه که قبلاً کنترل صریح نداشتند اکنون قابل تنظیم‌اند. نمایش فرم با اجازهٔ ثبت یکسان معرفی نمی‌شود؛ خاموش‌کردن صرف نمایش، API مالی را لغو نمی‌کند. برای قطع عملیات، کنترل «انجام عملیات» همان مورد باید خاموش شود.

۱۹ flag اختیاری فقط برای ناوبری‌اند. نقش ذخیره‌شده در startup بازنویسی نمی‌شود؛ absent از رفتار قبلی ارث می‌برد. patch فقط گزینه‌های تغییرکرده را می‌فرستد؛ سرور patch معتبر را روی snapshot normalized قبلی ادغام می‌کند. بولین ناشناختهٔ از قبل ذخیره‌شده فقط بدون تغییر پذیرفته می‌شود؛ افزودن یا تغییر اختیار ناشناخته رد می‌شود. دو اختیار داده/اعلان خزانه فعال‌اند و با توضیح سازگاری نمایش داده می‌شوند، نه alias بی‌اثر.

سرپرست چندشرکتی با اجتماع شرکت‌های مجاز انتخاب می‌شود؛ مدیر محدود فقط intersection شرکت‌های خودش را در metadata انتخاب می‌گیرد. خطای مجوز، شرکت، واحد و سقف جداست؛ ویرایش نامرتبط رابطهٔ قبلی را پاک نمی‌کند. landing فقط مقصد مجاز را باز می‌کند. تنظیم bulk ادمین اختیارات اجباری را تغییر نمی‌دهد؛ poll یکسان draft را پاک نمی‌کند. مبالغ، پرداخت‌ها، گردش تأیید، سقف‌ها، مجوزهای مالی پایه و schema SQLite۱ تغییر نکردند؛ migration/reset انجام نمی‌شود.

Staging جاری `OPS/private/permanent-staging-menu-permissions-v53` و آدرس ثابت `http://127.0.0.1:55120/` است؛ RUNNING از `2026-10-24T10:40:59.358Z` (۱۴:۱۰:۵۹ تهران). `ACCESS.txt` فقط در مسیر خصوصی محیط است؛ رمزها در Git، گزارش یا چت قرار نمی‌گیرند. محیط قبلی v52b و تمام بکاپ‌های قبلی نگه داشته شدند. پایگاه تازه schema۱ دارد و رمز اصلی admin یا دادهٔ Production اصلاً خوانده/تغییر داده نشده است.

انتقال فقط پس از توقف Stage قبلی، خروج هر دو PID و بسته‌شدن دو پورت انجام می‌شود. ابزار `OPS/tools/prepare-staging-menu-permissions-v53.mjs ARTIFACT MANIFEST_SHA` manifest/proof را تطبیق می‌دهد، SQLite سازگار را مستقل بازیابی و state hash/counts را مقایسه می‌کند؛ vault فقط opaque و بایت‌یکسان کپی می‌شود. schema و داده‌ها/رمزها حفظ می‌شوند. فقط استثنای قبلاً مصوب استعلام دستیِ تأییدشده در gateway خصوصی حفظ است؛ عملیات خودکار و سایر خروجی‌ها بسته‌اند و این تحویل مجوز مصرف جدید نیست.

## راهنمای آزمون مالک

با admin آزمایشی وارد شوید: «مدیریت کاربران و دسترسی‌ها ← مدیریت نقش‌ها و حدود اختیار». یکی از نقش‌های غیرادمین را انتخاب کنید؛ ۹ کارت مستقل را ببینید، به‌ویژه «ثبت درخواست‌های مالی و پرسنلی» و «کارتابل پیگیری درخواست‌ها». تغییر یک زیرمنوی نمایش و یک عملیات ثبت را جدا آزمایش کنید؛ ذخیره و ورود مجدد نقش آزمایشی را بررسی کنید. گروه‌های خزانه، اطلاعات پایه و استعلام مستقل‌اند. داده‌های تست را فقط همین‌جا بسازید؛ بررسی روی دامنهٔ اصلی انجام نشود.
