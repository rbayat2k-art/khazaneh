# v93b — اصلاح تشخیص پذیرش پیامک فراز

وضعیت: **STAGING / PASS؛ انتشار Production انجام نشده**، ۲۰۲۶/۱۰/۲۸. دامنه همچنان v92c است. مجوز و gate انتشار همین نامزد جدا بررسی می‌شود؛ نتیجهٔ فنی مجوز نشر نیست.

## نیاز و علت

مالک دریافت واقعی رمز و یادآوری را گزارش کرد، درحالی‌که لاگ خطای درگاه داشت و آزمون دقیق خواست. تطبیق خواندنی گزارش سرویس با گیرنده، متن، خط و زمان، ارسال یادآوری قبلی را تأیید کرد؛ وضعیت provider و item برابر sent بود، نه تأیید مستقل تحویل گوشی. یک آزمون بی‌خطرِ مجاز به مقصد مدیرِ قبلاً تأییدشده، بدون تغییر رمز و با intent پایدارِ یک‌بار اجرا شد. پاسخ POST واقعی HTTP200/status=success/data={id,...} بود. خروجی خام، شماره، کلید و OTP وارد گزارش نشدند. مستندات عمومی scalar data را نمونه می‌زنند؛ کد فقط همان شکل را می‌پذیرفت. این علت مثبت‌کاذبِ خطای ارسال بود.

## تغییر و مرز

تنها فایل اجرایی تغییرکرده src/server/sms-transport.ts است: FARAZ_PUBLIC اکنون scalar data یا own data.id را می‌خواند. HTTP200/201 و success و شناسهٔ معتبر لازم‌اند؛ جست‌وجوی بازگشتی، alias دلخواه، آرایه/boolean، صفر/منفی/اعشاری/نمایی، عدد نامطمئن و کلید محرمانه پذیرفته نمی‌شوند. سایر adapterها، timeout، سقف پاسخ، جلوگیری redirect، رمز و رویدادها تغییر نکردند. فایل‌های اجرایی frontend و storage-cli بایت‌یکسان‌اند؛ build-proof.json فقط هویت build تازه دارد.

لاگ‌های تاریخی FAILED و claimهای UNKNOWN بازنویسی یا بازپخش نشدند. پیام ممکن است قبلاً رسیده باشد؛ سهمیهٔ مصرف‌شده برنمی‌گردد و retry خودکار تازه‌ای وجود ندارد. رمز، نقش، شرکت، سقف، چهار مسیر مالی و خرید تغییر نکردند. هیچ کلید/خط یا متن زنده‌ای عوض نشد.

## آزمون واقعی اجراشده

- full-b-sqlite: 761 PASS؛ full-b-json: 761 PASS؛ بدون fail/skip/cancel. lint/build/proof PASS.
- تست قرمز علیه parser قبلی، چهار پاسخ object واقعی‌نما را رد می‌کرد؛ نسخهٔ اصلاحی هفت تست جدید قرارداد را پاس کرد. fixtureهای OTP، آزمون مدیر، اعلان و scheduler با data.id اجرا شدند. HTTP200/201، متن/پترن، scalar قبلی، پاسخ خطا و ID ناسالم پوشش دارند.
- scheduler صف واقعی با تجمیع، دو یادآوری، restart و عدم افشای ledger؛ حداقل۴۵دقیقه، ۸تا۲۱تهران، سقف مشترک شماره، حذف کار تمام‌شده، مجوز/شرکت جاری، claim/result failure و قطع پاسخ PASS. آزمون‌های OTP و چهارگردش قبلی در همان gateها PASS.
- مرورگر مستقل با دادهٔ مصنوعی، provider کاملاً مسدود/شبیه‌سازی‌شده و پاسخ object: وضعیت سبز پذیرفته‌شدن و SENT روی دسکتاپ/۳۹۰ PASS؛ هیچ پیام واقعی از مرورگر نرفت. این شاهد «تحویل گوشی» را ادعا نمی‌کند. سرور QA متوقف و داده‌اش حفظ شد.
- بازبین مستقل فقط خواندنی، نقص شناسهٔ متنی منفی/صفر را VALID دانست؛ رفع و regression افزوده شد؛ بازبینی نهایی یافتهٔ باز نداشت. بازبین تست یا شبکه اجرا نکرد. full-a-sqlite قبل از آخرین اصلاح اجرا شده بود و شاهد نهایی این نامزد نیست.
