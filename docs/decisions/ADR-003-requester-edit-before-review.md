# ADR-003 — ویرایش توسط ثبت‌کننده پیش از شروع رسیدگی

Status: Accepted — درخواست مالک، ۲۰۲۶/۱۰/۲۱؛ نتیجهٔ آزمون/انتشار در README.

## قرارداد و محدوده

متقاضیِ همان درخواست با مجوز ثبتِ نوع مربوط، تا پیش از نخستین اقدام موفق بررسی‌کنندهٔ بعدی می‌تواند اطلاعات و پیوست‌های درخواست را ویرایش کند. صرف مشاهده/بازکردن صفحه اقدام محسوب نمی‌شود. سرور این شرط را دوباره داخل صف اتمیکِ موجود می‌سنجد، نه فقط با مخفی‌کردن دکمه.

تصمیم صریح مالک برای گروه: هر ردیف مستقل است؛ شروع رسیدگی به یک ردیف، ویرایش ردیف‌های دست‌نخورده را نمی‌بندد. عنوان/پیوست عمومی گروه، عضویت ردیف‌ها، هویت متقاضی و ارجاع‌ها در این ویرایش تغییر نمی‌کنند. جمع گروه از ردیف‌های موجود بازحساب می‌شود. برای تکی، همان اطلاعات فرم اصلی قابل اصلاح است.

## حفاظت و سازگاری

- مرحله، تأییدکننده، وضعیت، سقف اختیار، فیش و پرداخت قابل جعل/ویرایش نیستند. ویرایش، مرحلهٔ جاری را جلو نمی‌برد و اعلان تازهٔ ثبت اولیه نمی‌سازد.
- نسخهٔ موجود افزایش می‌یابد؛ فرمان ویرایش نسخهٔ مورد انتظار می‌خواهد. بررسی‌کننده نیز برای درخواست ویرایش‌شده باید نسخهٔ دیده‌شده را بفرستد؛ اقدام هم‌زمان یا تب قدیمی نمی‌تواند تغییر تازه را ناخواسته تأیید کند.
- نخستین اقدام موفق بررسی، حتی یادداشت/ویرایش بدون تأیید، پایان این مجوز است. مسیر «برگشت برای اصلاح/ارسال مجدد» قبلی مستقل و محفوظ می‌ماند.
- برای دادهٔ قدیمی، فقدان فیلد جدید به‌تنهایی «رسیدگی‌نشده» نیست؛ وضعیت، سوابق تصمیم/یادداشت و آثار تأیید/برگشت بررسی می‌شوند. سابقهٔ مبهم fail-closed است، نه پاک‌سازی یا ساخت تأیید مصنوعی.
- هیچ دادهٔ زنده‌ای در تست استفاده نمی‌شود. قبل ویرایش snapshot کد و قبل انتشار snapshot سازگار داده/تنظیمات گرفته می‌شود؛ JSON محلی روی سرور جایگزین نمی‌شود.

## پذیرش

ثبت و ویرایش تکی/ردیف گروه، reload و ماندگاری، حفظ مسیر بدون سرپرست، جمع گروه، پیوست‌ها، منع هویت دیگر/مجوز لغوشده، رد بعد از یادداشت/تأیید/برگشت، ویرایش‌های هم‌زمان و مسابقه ویرایش/بررسی، و حفظ ظاهر RTL/موبایل با API و مرورگر واقعیِ دادهٔ مصنوعی آزموده می‌شوند. انتشار فقط پس از gateها و با تأیید مالک است.
