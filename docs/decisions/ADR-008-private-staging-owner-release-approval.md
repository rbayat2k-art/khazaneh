# ADR-008: Staging خصوصی و تأیید مالک پیش از Production

## وضعیت و مبنا

پذیرفته‌شده توسط مالک، ۲۰۲۶/۱۰/۲۲. درخواست راه‌اندازی فرایند دائمی و Staging، **مجوز انتشار Production نیست**. مجوزهای انتشار قدیمی، این قفل تازه را دور نمی‌زنند. هدف: ساخت و آزمون فنی توسط Codex، بازدید مرورگری مالک، سپس انتشار همان نسخه فقط پس از تأیید صریح.

## تصمیم

چرخهٔ الزامی: نیاز فارسی → هدف/دامنه/معیار پذیرش → شاخهٔ `codex/...` و حفاظت → پیاده‌سازی محلی → آزمون متناسب با ریسک و مرورگر → freeze/manifest → Staging → آزمون مالک → **«تأیید است، منتشر کن» برای همان شناسهٔ نسخه و دامنه** → gate انتشار و بکاپ/restore/migration/rollback → Production → کنترل و گزارش.

- درخواست ساخت، اصلاح یا تست، تأیید انتشار نیست. مجوز به نسخهٔ معرفی‌شده متصل است؛ هر اصلاح بعدی که رفتار/فایل‌های قابل انتشار را عوض کند نیازمند پذیرش دوبارهٔ نسخهٔ تازه است. هش یکسان اجازهٔ صرف‌نظر از gate خراب یا ریسک حل‌نشده نمی‌دهد.
- تصمیم‌های حساسِ پول، مجوز، نگهداری و گردش کار همچنان متعلق به مالک‌اند؛ برای جزئیات فنی معمول و scope قبلاً مجاز، تأیید تکراری نخواهید. فقط skill/نقش لازم انتخاب شود؛ نصب دوباره یا اجرای همهٔ نقش‌ها ممنوع است.
- داده، نشست، فایل، رمز و env واقعی از Production به Staging کپی نشوند. promote فقط artifact و migration نسخه‌دارِ آزموده‌شده است؛ دادهٔ آزمایشی هرگز به Production منتقل نمی‌شود.
- مجوز انتشار مستقل از Git commit/push است؛ درخواست توسعه مجوز دائمیِ push یا انتشار خودکار نمی‌سازد.

## انتخاب محیط در این مرحله

ساخت `staging.shahrahsystem.ir` فقط با اثبات DNS، TLS، کنترل دسترسی، جدایی route/config/data و محدودیت خروجی‌ها پذیرفتنی است. بررسی فعلی: DNS این نام وجود ندارد و دسترسی خواندن vhostهای cPanel فراهم نیست؛ مسیر امن آن اثبات نشد. هیچ تنظیم دامنه/Apache یا سرویس Production عوض نمی‌شود.

جایگزینِ مجاز مالک: Staging خصوصیِ محلی روی `127.0.0.1:55120` با دروازهٔ ورود، backend مستقل loopback55121 و SQLite تازه. خروجی منجمد v28، نه Vite dev server، اجرا می‌شود. داده و پنج حساب کاملاً مصنوعی‌اند. env از allowlist کوتاه ساخته می‌شود؛ بانک/پیامک خاموش و fetch/socket/DNS غیرliteral/UDP/subprocess در backend مسدود است. CSP مرورگر ارتباط خارجی را منع می‌کند. این guard محدود به برنامهٔ Node است، نه sandbox سیستم‌عامل یا تضمین علیه کد مخربِ دارای اختیار OS.

Staging محلی به روشن‌بودن این کامپیوتر وابسته است؛ سرویس ابری۲۴ساعته یا دسترسی از دستگاه دیگر نیست. مسیرها و launcher پایدارند و داده با stop/start حفظ می‌شود؛ پس از reboot با launcher اجرا می‌شود. اجرای خودکار در logon، تونل عمومی، DNS و تغییرات میزبان در این مرحله ساخته نمی‌شوند.

## تبعات و کنترل

UI و منطق مالی محصول دست‌نخورده‌اند. Node24/Windows Staging با Node22/Linux Production یکسان نیست؛ آزمون Linux/ظرفیت مرتبط برای تغییرات پرریسک پیش انتشار همچنان لازم است. تکرار آزمون کامل محصولِ hash-identical در این راه‌اندازی لازم نیست؛ ایمنی ابزارها، browser/API واقعی، جدایی و restart خودِ محیط باید تازه آزموده شوند. جزئیات جاری در [راهنمای عملیات](../operations/development-staging-release.md) ثبت است.
