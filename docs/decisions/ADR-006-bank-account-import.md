# ADR-006 — ورود گروهی حساب بانکی با بازبینی و حفظ داده موجود

مصوب مالک،2026-10-21. مسیر فعال React/Express/JSON در `C:/Users/reza/Desktop/khazaneh` است؛ نه آرشیو قدیمی. scope فقط افزودن گروهی حساب‌های مبدأ، قالب xlsx و بازبینی است؛ صورت‌حساب، OCR، بانک واقعی، تغییر مجوز و ویرایش جمعی خارج‌اند.

قالب دو شیت «حساب‌ها»/«راهنما»،۱۳ستون مطابق فرم فعلی،۴ستون الزامی بانک/عنوان/شرکت یا صاحب حساب/شماره حساب دارد. شماره‌ها متن‌اند تا صفر/دقت از دست نرود؛ ورود numeric شناسه، formula/error، ستون ناشناخته و قالب مبهم رد می‌شود. بانک/نوع/وضعیت کشویی، سایر گزینه‌ها طبق قرارداد فرم فعلی. سطرهای واقعاً خالی نادیده‌اند؛ حداکثر۲۰۰حساب و فایل1MiB. parse فقط محلی در مرورگر است؛ binary مالی به ارائه‌دهنده بیرونی ارسال نمی‌شود.

ورود فقط حساب جدید می‌سازد؛ موجودی حساب و تراکنش‌ها/تصویر ثابت/شناسه/پیش‌فرض هیچ حساب قبلی عوض نمی‌شود. تکرار یکسان در فایل یا بانک/حساب/شبا/کارت موجود گزارش و skip می‌شود؛ اختلاف هر فیلد صریح یا برخورد شناسه با حساب دیگر خطاست. نبود ستون/مقدار اختیاری در ردیف تکراری درخواست تغییر آن فیلد نیست. برای حساب جدید، پیش‌فرض نوع جاری، وضعیت فعال و روش‌های فرم فعلی است. «خیر/خالی» در پیش‌فرض به معنی تغییر پیش‌فرض موجود نیست؛ «بله» برای حساب جدید با پیش‌فرض موجود خطاست. اگر هیچ پیش‌فرضی نیست، حداکثر یک حساب جدیدِ صریح می‌تواند پیش‌فرض شود؛ حساب قدیمی خودکار ترفیع نمی‌یابد.

از مجوز موجود canManageBankAccounts و نشست فعلی، ساختار حساب و صف نوشتن/commit اتمیک JSON استفاده می‌شود؛ UI تنها مرز دسترسی نیست. `import-preview` با rows صریح فقط گزارش می‌دهد. `import` همان rows و fingerprint بازبینی را می‌گیرد و با actor/current accounts دوباره محاسبه می‌کند. fingerprint فقط optimistic concurrency است، نه مجوز یا امضای امنیتی؛ مجوز مستقل در هر فرمان enforce می‌شود. تغییر حساب‌ها یا هویت/ورودی،409 و بازبینی مجدد می‌خواهد. رد کل فایل قبل هر تغییر؛ ایجاد همهٔ NEWها در یک save؛ UUID و audit شمارشی بدون شماره/PII در summary. صرف پاسخ ازدست‌رفته باعث retry خودکار نیست؛ بازبینی بعدی، حساب ثبت‌شده را تکراری نشان می‌دهد. فایل تماماً تکراری save/audit جدید ندارد.

UI: کنار دکمه فعلی افزودن حساب، «ورود گروهی از اکسل»؛ پنجره همان کلاس‌های فرم فعلی، دانلود قالب، انتخاب/drag-drop، بازبینی ردیف و علت و شمارش، ثبت صریح NEWها. ERROR ثبت را می‌بندد؛ خطای ارتباط/مجوز/ذخیره ورودی را حفظ می‌کند. تغییر فایل نتیجه قبلی را باطل می‌کند؛ در حال parse/ثبت بستن/ارسال دوباره غیرفعال است. RTL/موبایل/فوکوس و Escape بررسی می‌شوند.

معیار پذیرش: قالب واقعی با dv و شناسه متنی؛ parse قابل‌پیش‌بینی، خطای دقیق ردیف؛ server denied actor/revocation/impersonation/unknownfields؛ preview بدون نوشتن؛ identical skip،conflict block و عدم تغییر موجود/پیش‌فرض؛ race و تکرار/خطای save بدون اثر ناقص؛ reload و انتخاب حساب واردشده در UI؛ regression چرخه قبلی؛ بازبینی مستقل، gateهای artifact نهایی و snapshot سازگار خصوصی قبل انتشار. هیچ داده واقعی وارد تست، تصویر یا fixture نمی‌شود. شواهد اجرای نهایی در README جاری ثبت می‌شود.

بازبینی مستقل: کنترل ZIP اکنون اندازه local/CD را پیش از inflate تطبیق می‌دهد و encrypted/data-descriptor و DEFLATE با اندازهٔ صفر/نامعلوم را رد می‌کند؛ سقف بازشده۸MiB و Worker با timeout۷ثانیه برقرار است. regression برای اندازه local جعلی، descriptor و اندازه صفر در فایل واقعاً فشرده پاس شد. فایل ناسازگار باید با قالب دوباره ذخیره شود، نه اینکه guard ضعیف شود.

آزمون مصرف‌کننده، باگ مرتبط «تغییر حساب مبدأ» را بازتولید کرد: effect وابسته به شناسهٔ خالی فوراً پیش‌فرض را مجدد انتخاب می‌کرد. انتخاب خودکار فقط برای اولین حساب فعال اعمال می‌شود؛ پاک‌کردن عمدی انتخاب برای جست‌وجو حفظ می‌شود. هیچ default ذخیره‌شده، مجوز یا فرمان پرداخت تغییر نمی‌کند. آزمون مرورگر حساب واردشده فعال را با کیبورد انتخاب و غیرفعال را از نتایج خارج می‌بیند؛ هیچ پرداختی برای این آزمون ثبت نمی‌شود.
