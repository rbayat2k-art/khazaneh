# ADR-027: ورود مدیر اصلی به پرتال کاربر

درخواست صریح مالک در ۲۰۲۶/۱۰/۲۵: کنار عملیات مدیریت کاربر، «ورود به این دسترسی» فقط برای نقش اصلی ADMIN. مدیر می‌تواند با اختیار کاربر مقصد کار واقعی انجام دهد. خروجی ابتدا Staging؛ انتشار دامنه به پذیرش همان نسخه نیاز دارد.

معیار پذیرش: فقط ADMIN اصلی با نشست عادی و فعال؛ مقصد فعال غیرمدیر؛ دلیل اجباری و نشست جدا با توکن تصادفی و حداکثر ۳۰ دقیقه، متصل به همان نشست مدیر. اعتبار والد/مدیر/مقصد در هر خواندن و دوباره داخل صف نوشتن سنجیده می‌شود. مجوز/شرکت/سقف/سرپرست/خودتأییدی از مقصد می‌آید. توکن والد هرگز در پاسخ یا child نگهداری نمی‌شود؛ فقط هش یکطرفه برای پیوند. پایان با اعتبار نشست والد است و توکن مقصد به ADMIN تبدیل نمی‌شود. آغاز/پایان تکرارپذیرند؛ شکست commit نباید نشست یا سابقهٔ نیمه‌کاره بسازد.

پرتال کاربر در همان تب و sessionStorage مستقل باز می‌شود؛ localStorage نشست مدیر محفوظ است و تب‌های دیگر تغییر نمی‌کنند. ورود/بازگشت reload کامل دارند تا فرم، modal، projection، cursor و پاسخ درراه قبلی منتقل نشوند. نوار ثابت هردو نام و بازگشت را نشان می‌دهد؛ حتی صفحه تغییر رمز/بارگذاری نیز راه بازگشت دارد. تغییر رمز خود/۲مرحله‌ای و بستن نشست‌های واقعی کاربر در حالت نمایندگی رد می‌شود؛ مدیر از پرتال خودش مدیریت امنیت می‌کند. اعلان‌های داخل سامانه همان مقصد هستند؛ اعلان سیستم‌عامل در نمایندگی تولید یا مصرف نمی‌شود.

انتساب: شناسه ورود، مدیر واقعی و دلیل در همان commit روی رویدادهای جدید گردش/یادداشت/پرداخت و رکوردهای تازه و job استعلام ثبت می‌شوند. مجوز و شناسهٔ اقدام‌کنندهٔ دامنه همچنان کاربر مقصد است؛ سابقهٔ قدیمی بازنویسی نمی‌شود. یک security event با مسیر فرمان و شناسه رکوردهای متأثر، بدون body/رمز/token/اطلاعات بانکی، ثبت می‌شود. نمایش گردش/گزارش هر دو هویت را نگه می‌دارد. job زمینه provenance پایدار دارد. schema SQLite تغییر نمی‌کند؛ این افزودهٔ قرارداد session است، پس downgrade به binary قدیمی فقط پس از ابطال همه child sessionها یا استفاده از binary سازگار مجاز است. rollback دادهٔ قدیمی ممنوع است.

مسیر متصل: AdminPortalView → AdminUserEntry → auth/impersonation/start/end → resolvePortalSession/صف فرمان → saveDb و attribution → RequestDetails/OfficialReviewNotes/گزارش جامع. denied غیرمدیر/ADMIN تکمیلی/تودرتو، جدایی دامنه و خودتأییدی، اعلان، شروع/پایان retry، commit failure، revoke/expiry/role change/restart و مرورگر دو تب/refresh/برگشت آزموده شدند. [گزارش v62b و هویت artifact](../operations/staging-v62-admin-user-entry.md) و ops/work/admin-user-session-v62-20261025/final-evidence-b.json مرجع نتیجه‌اند. تغییر credential/connections نیز در نمایندگی بسته است، چون vault boundary مستقل از audit DB دارد؛ مدیر از نشست اصلی خودش مدیریت می‌کند. شکل بزرگ/کوچک حروف و اسلش پایانی در منع امنیت canonical می‌شوند. نوار بازگشت زیر لایهٔ پنجره‌های عملیاتی است تا دکمه‌های آن‌ها پوشیده نشوند. داده/رمز/نقش‌های جاری Stage حفظ شدند؛ هیچ اتصال Production یا پیامک/بانک در این کار انجام نشد.
