# ADR-016 — خروجی عملیاتی خزانه و گزارش جامع مستقل

## وضعیت و تاریخ

مصوب مالک، ۲۰۲۶/۱۰/۲۳؛ پیاده‌سازی v49 فقط Staging، پذیرش و Production هنوز NOT RUN. این تصمیم ADR-015 (هر نوبت پرداخت یک ردیف) و ADR-008 (پذیرش مالک) را حفظ می‌کند.

## مسئله و تصمیم

اکسل صف/مخزن/پرداخت‌شده ابزار پرداخت است، نه گزارش گردش تأیید. ستون‌های آن به شناسه، گیرنده، شرح سند حسابداری/بابت، مرکز هزینه، کارت/حساب/شبا و بانک مقصد، مبلغ و زمان‌های ثبت/اقدام محدود شدند؛ برای پرداخت‌شده، شناسه نوبت و حساب/بانک مبدأ و مرجع همان نوبت اضافه می‌شوند. صف و مخزن مبلغ **مانده قابل پرداخت** و پرداخت‌شده مبلغ **همان اجرا** را می‌دهند. انتخاب گروهی فقط فرزندان انتخاب‌شده را شامل می‌شود؛ درخواست اصلی یا مبلغ مصوب دوباره جمع نمی‌شود. شماره حساب از کارت حدس زده نمی‌شود؛ فقط نتیجه تأییدشده جاری استعلام قابل اتکاست. بانک مبدأ دستی، بانک مقصد نیست.

گزارش جامع در منوی مستقل «گزارش‌ها و خروجی‌ها» با فیلتر تاریخ ثبت یا **تاریخ واقعی بانکی هر نوبت**، بازه شمسی شامل دو سر، شرکت، نوع پرداخت/مساعده/دستی، تکی/گروهی و وضعیت قرار می‌گیرد. گزارش چهار برگه دارد: درخواست‌ها/ردیف‌ها، نوبت‌های پرداخت، گردش/یادداشت‌ها و مشخصات گزارش. مجموع مبلغ مصوب درخواست‌های متمایز، پرداخت کل، مانده و مبلغ اجراهای منتخب مستقل‌اند؛ با تاریخ پرداخت فقط اجراهای همان بازه جمع می‌شوند. گردشِ درخواست‌های منتخب تاریخچه کامل آن‌هاست، نه فقط یادداشت‌های بازه بانکی. پرداخت دستی یک اجرای ثبت‌شده است، نه انتقال بانک جدید.

## قرارداد و دسترسی

- GET `/api/reports/treasury`: preview صفحه‌بندی‌شده؛ GET `/api/reports/treasury/export`: همه نتایج همان فیلتر، نه صفحه جاری. DTO allowlist؛ بدون فایل، کلید، تنظیمات، رمز یا payload خام.
- پارامترها: `basis=REGISTRATION|PAYMENT`, `from/to=YYYY/MM/DD`, `kind=ALL|PAYMENT|ADVANCE|MANUAL`, `structure=ALL|SINGLE|GROUP`, `status`, `company`, `view=REQUESTS|PAYMENTS|HISTORY`, `page>=1`, `limit=1..200`. فیلتر ناشناخته، تاریخ نامعتبر و بازه معکوس 400؛ شرکت نامجاز 403؛ خروجی تاریخچه ناسازگار 409؛ بیش از۵۰هزار ردیف ترکیبی 413. محدودسازی پنهانی ممنوع است.
- مجوز مستقل `canAccessTreasuryReports` در UI و سرور؛ پیش‌فرض فقط کلید واقعی ADMIN/ACCOUNTING/TREASURY. false صریح حفظ؛ custom با template مالی خودکار مجاز نیست. دانلود علاوه بر آن `canExportReports` می‌خواهد. هر دانلود با جلسه و اختیار جاری درخواست تازه می‌دهد؛ role/company/department/actor تغییر کند، preview و پاسخ دیررس قبلی باطل می‌شوند.
- مصوب صریح مالک: دستی‌های سایر کاربران نیز در گزارش حسابداری و خزانه، **فقط شرکت‌ها و دامنه فعلی مجاز** دیده شوند. گسترش صرفاً report-only است؛ `/state`، workspace، اختیار پرداخت/تأیید، سقف و شرکت تازه اعطا نمی‌شود. ID شرکت authoritative است؛ نام/snapshot/مالک fallback فقط legacy فاقد ID. چندنقشی همان اجتماع شرکت‌های مصوب است.

## سازگاری و حدود

schema و رکوردهای مالی بازنویسی نمی‌شوند؛ کلید مجوز اختیاری در normalization است، نه migration یا backfill. همه تاریخ‌ها در خروجی شمسی و ساعت تهران؛ زمان مجهول اختراع نمی‌شود. legacy فاقد اجرای تفکیک‌شده، هشدار دارد و وارد بازه پرداخت حدسی نمی‌شود؛ ناسازگاری مانع Excel جامع است. Excel مبلغ بسیار بزرگ را متن دقیق، شناسه‌ها را متن با صفر ابتدایی و رشته شبیه فرمول را متن غیرقابل‌اجرا می‌نویسد. کتابخانه فعلی تغییر نکرد.

گزارش هم‌زمان snapshot خواندنی همان پاسخ سرور است، نه دفترکل حسابداری جدید یا تضمین داده قدیمی. سقف۵۰هزار ردیف، ظرفیت آزموده‌شده آینده نیست. گزارش بزرگ‌تر به بازه محدودتر نیاز دارد؛ backend async job/streaming خارج این مرحله است. API پرداخت و idempotency، رسیدها، استعلام واقعی و تمام نویسنده‌های مالی تغییر نمی‌کنند. بازگشت کد فقط همراه **داده و vault جاری**؛ backup قدیمی نباید روی ثبت‌های تازه restore شود. شواهد نسخه و دستورهای بازتولید در checkpoint v49 راهنمای عملیات ثبت می‌شوند.
