# ADR-004 — کد خودکار و تعریف گروهی اطلاعات پایه

Accepted: درخواست و تأیید انتشار مالک، ۲۰۲۶/۱۰/۲۱. وضعیت آزمون و انتشار در README.

کد شرکت، واحد و مرکز هزینهٔ جدید به‌ترتیب از001001،002001،003001 خودکار و رشته‌ای است. پیشوند هر نوع ثابت و پسوند افزایشی با حداقل سه رقم است؛ کدها در همه شرکت‌ها برای همان نوع یکتا هستند. سوابق، شناسه‌ها و کدهای قبلی بازشماری نمی‌شوند؛ کد موجود هنگام ویرایش ثابت می‌ماند. مقدار code ارسالیِ کلاینت قدیمی در ایجاد، کد دستی تولید نمی‌کند. شمارندهٔ اختیاریِ افزایشی در همان JSON موجود، همراه رکورد در همان save اتمیک ثبت می‌شود؛ از کدهای موجود آغاز و پس از حذف کاهش نمی‌یابد. پیش‌نمایش UI رزرو کد نیست؛ سرور داخل صف نویسنده موجود تعیین می‌کند.

واحد و مرکز هزینه، علاوه بر فرم تکی، پنجره چندردیفی با شرکت مشترک صریح، واحد اختیاریِ همان شرکت برای مراکز هزینه، افزودن/حذف ردیف و پیست ستون نام‌ها دارند. عنوان و توضیح هر ردیف پیش از ثبت قابل بررسی است. کدها خودکارند. ثبت گروه حداکثر۲۰۰ردیف، فقط ایجاد و همه‌یا‌هیچ است؛ شناسه/کد/وضعیت از ردیف وارد نمی‌شود. شرکت نامعتبر/غیرفعال، واحد نامرتبط و تکرار نام در همان شرکت، کل گروه را با شماره ردیف رد می‌کند. خطا یا قطع پاسخ retry خودکار ندارد؛ ارسال دوبارهٔ نام‌های ثبت‌شده اثر تکراری نمی‌سازد. مجوز موجود مدیریت همان نوع، از نشست جاری، دوباره در نوبت نوشتن سنجیده می‌شود؛ اعطای مجوز تازه یا تغییر قواعد مالی در محدوده نیست.

مسیر: AdminMasterDataAndSmsSection/فرم گروهی → App → endpoint مجاز master-data → ماژول محدود ایجاد/تخصیص → همان saveDb/صف موجود → state → فهرست‌ها و انتخاب‌گرهای قبلی. مرجع ظاهر، فرم اطلاعات پایه و پنجره ویرایش فعلی است؛ صفحه اصلی بازطراحی نمی‌شود. اطلاعات بانکی/واقعی در تست و لاگ جدید وارد نمی‌شود. قبل ویرایش نقطه بازیابی کد و قبل انتشار snapshot خصوصی سازگار گرفته می‌شود؛ DB محلی جای سرور نمی‌رود.

پذیرش: ابتدا آزمون شکست‌خورنده؛ آغاز و ادامه کدها/صفر ابتدایی، حفظ کد قبلی، هم‌زمانی و حذف، خطا/تکرار/روابط/مجوز و rollback بدون ذخیره ناقص؛ سپس UI تکی/گروهی، پیست، خطا/خالی/انتظار، reload و RTL دسکتاپ/موبایل. بازبینی مستقل safeguards و gateهای نهایی لازم‌اند.
