# Temporary hosting on the owner's Windows computer

Date: 2026-10-21. Status: accepted for a temporary test deployment.

The owner requested that this computer host the application for multiple authenticated users before moving to a VPS. The initial instruction to preserve data was superseded by an explicit request to clear application data for testing. A byte-for-byte backup was retained before the reset. The fresh database contains one bootstrap administrator and five built-in role templates, with no companies, departments, cost centers, bank accounts or financial records.

## Decisions

- Express serves a production Vite build on loopback port 3000. The Vite development server is not exposed.
- The standard localhost.run SSH reverse tunnel supplies temporary HTTPS access without opening an inbound router/firewall port. Cloudflare Quick Tunnel was tried first, but its TCP/UDP 7844 edge connection remained unavailable after VPN TUN was enabled. The working SSH service terminates public TLS and forwards over encrypted SSH to loopback; business data is persisted on this computer. Temporary hostnames can change. The first-contact SSH host keys are pinned in a task-specific known-hosts file; personal SSH keys and the user’s global SSH configuration are not used.
- Every protected API requires a nonexpired, nonrevoked session for an active user. Actor IDs are derived from that session. Permission, record scope, workflow stage, self-approval and financial limits are checked server-side. All returned state, including mutation responses, is scoped for the authenticated viewer.
- Reset is unavailable over HTTP. Production startup refuses a missing or unreadable database instead of replacing it with sample data. Empty master-data lists stay empty. Demo login buttons and prefilled beneficiary examples were removed from the production experience.
- Bootstrap and newly reset accounts must change their temporary passwords. The original minimum of 12 characters was superseded by the owner's explicit 2026-10-21 request for a minimum of 5 characters (letters/numbers allowed), across UI and server validation. Existing credentials are not reset or shortened. The bootstrap secret remains only in a local owner file, outside public assets; its historical value is not proof of the current password.
- Keep the existing JSON store for this temporary phase. One process owns each store, mutations are serialized, writes use fsync plus atomic replacement, and the first write of each day keeps a backup. This is not a distributed database or a replacement for a tested off-device backup. Background SMS completion merges its log without rewriting an old business snapshot.
- A separate synthetic store with external integrations disabled is used for automated API and browser tests. Those fixtures and test credentials are never copied to the hosted database.

## Verification and limits

Ten access/workflow tests passed, including concurrent writes, rejected cross-user reads/actions, approval limits, forced password changes, blocked payment before accounting approval, duplicate settlement prevention and immediate session invalidation for disabled users. A browser journey created a company, department and user, changed the new user's password, submitted a persisted request and refreshed successfully without admin menus. Type checking and production build passed. This is a focused access and workflow check, not a full-system security, load or accounting-accuracy audit.

Before permanent deployment, move to a managed relational database, add recovery-tested off-device backups, deployment monitoring and a stable hostname. The current host must remain running, connected and awake. Existing local proxy settings are not changed; if port 10808 is already available, the host process may use it for outbound tunnel API access.

## Domain cutover amendment — 2026-10-21

The owner authorized moving this implementation to the existing Shahrah host/domain, with an explicitly clean start after backup. No database redesign was requested: the current implementation still uses one private JSON store and one process, not Prisma or a relational database. The earlier relational-database recommendation remains deferred work, not a completed migration. The Windows tunnel is stopped; HTTPS now proxies to loopback:32193 on the Linux host. NODE_ENV is production, integrations are disabled, and only dist assets are public. Private data is outside the release and web root (700 directory/600 file).

The encrypted pre-reset archive restored all 83 files with matching hashes. Only the original administrator and five base roles remain, with no financial/master data. Administrator hash/salt were verified unchanged. A read-only reviewer found no immediate blocker in password preservation or production bundling; the primary confirmed all Windows writers were stopped and the release output was empty before packaging. The release builder now rejects a nonempty output directory. The reset script is a completed one-time operation, not a general HTTP reset endpoint; do not run it again against post-cutover data.

Three pre-publication safeguards were verified and corrected: mutation serialization now holds through async handler completion even if the client disconnects, authorization is checked when a queued write starts, untrusted Cloudflare headers no longer reset login throttles, and daily-cover actor identity is bound to the authenticated user. The 17 API/queue tests passed, including denied scope/actor, duplicate settlement and password boundary cases. Type checking/build passed. A real browser against the packaged production server and synthetic store passed account creation, first-login password change and persisted request creation. Final live-domain checks used anonymous read-only requests only. Login responsive overflow was reproduced, fixed and verified.
